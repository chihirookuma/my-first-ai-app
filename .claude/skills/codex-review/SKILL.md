# Codex レビュー

Codex CLI（OpenAI）に読み取り専用でレビューを依頼し、その指摘を Claude が検証してから採否を判断する。

## 前提（環境の設定）

この環境では、APIキーをチャットやファイルに置かない。次の2つを、クラウド環境の設定画面でユーザー本人が登録する。

- ネットワークアクセスの許可ドメインに `api.openai.com`（パッケージマネージャーはオン）
- ネットワークシークレット：種類 Bearer、許可ウェブサイト `api.openai.com`、ヘッダー `Authorization`、プレフィックス `Bearer`、値にAPIキー

プロキシがリクエストにキーを付けるため、Claude からキーは見えない。ユーザーにキーをチャットへ貼らせない。

## 手順

1. レビュー対象を、スクラッチパッド内の新しいディレクトリに Markdown などのテキストとして保存する。Claude Docs のドキュメントは `export`（markdown）で取り出す。個人情報（実在の社員の評価・給与など）は含めない。
2. 依頼文を日本語で書く。観点・重要度（高・中・低）・修正案・件数の上限・総評を指定する。
3. 実行する（数分〜十数分かかるため、Bash の timeout は長めにする）。

   ```bash
   .claude/skills/codex-review/scripts/run_codex.sh <作業ディレクトリ> "<依頼文>" [出力ファイル]
   ```

   Codex CLI が未インストールなら、スクリプトが自動でインストールする（数分かかる）。

4. 出力ファイルを読む。

## 失敗したとき

| 表示 | 原因 | ユーザーへの案内 |
| --- | --- | --- |
| 接続できません (HTTP 000/403) | 許可ドメインかネットワークシークレットが未設定 | 環境設定の2か所を確認してもらう（`read_documentation` の environment.network を参照） |
| Quota exceeded | OpenAI の API クレジット残高がない | platform.openai.com の Billing で入金。ChatGPT の有料プランとは別料金 |
| インストールに失敗 | npm の取得失敗 | もう一度実行する |

`failed to connect to websocket` のエラーは無視してよい。HTTPS に自動で切り替わる。

## 結果の扱い

- Codex の指摘は「別の意見」であり、正解ではない。数値や法令の主張は、可能な範囲で一次資料や再計算で確かめる。確認できない数値は「Codexの指摘・要確認」と明記する。
- 指摘ごとに「採用・一部採用・保留・見送り」と理由を付け、表でユーザーに示す。
- ユーザーがすでに決めた方針と食い違う指摘は、勝手に反映せず、判断をユーザーに求める。
- Codex の出力を Claude の意見として混ぜない。どれが Codex の指摘かを明確にする。
- 使用トークン数を伝え、料金は OpenAI の Usage 画面で確認できると案内する。
